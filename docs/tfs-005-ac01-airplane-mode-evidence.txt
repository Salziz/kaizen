Kaizen TFS-005 — AC01 Airplane Mode / Unreachable Network Evidence
Criterion: Sending a message while the phone is in airplane mode or the network
is down shows:
"Can't reach Kaizen right now. Nothing you typed was lost — check your connection and try again."
as an inline message in the chat thread. The input field is cleared. The user's
message is preserved in the thread with a visual indication that it failed to send
(muted styling, status: failed, retry affordance).

Device / OS Target:
- Real device verification target: SM A175F (Android 16 / API 36) / Android Emulator Pixel_8 (Android 17 / API 37, emu64xa16k)
- Network state: Airplane mode ENABLED (adb shell cmd connectivity airplane-mode enable, settings global airplane_mode_on = 1)
- Host connectivity: Completely disconnected from backend service / DNS unreachable

Procedure:
1. Launched Kaizen app with airplane mode enabled on the Android device/system.
2. Verified initial UI state: chat composer is ready, send button is enabled when text is entered.
3. Typed message into composer: "Building an offline coffee store app".
4. Tapped Send button.
5. Observed immediate UX transition:
   - Composer text field was immediately cleared upon send (user does not have to delete text manually).
   - User message bubble appeared in the chat thread.
   - The OS-level network call to api.groq.com failed due to network unreachability (ClientException / SocketException: OS Error: Network is unreachable, errno = 101 / No address associated with hostname).
   - ChatController identified the network unreachability via isNetworkUnreachable() and set:
     errorMessage = "Can't reach Kaizen right now. Nothing you typed was lost — check your connection and try again."
   - The user message status transitioned to MessageStatus.failed (with error styling and retry tap target).
   - An inline retry banner appeared at the bottom displaying the verbatim error copy:
     "Can't reach Kaizen right now. Nothing you typed was lost — check your connection and try again."
6. Verified persistence:
   - ConversationStore.loadThread() confirms the message is stored with status 'failed', preserving the exact typed text.
7. Connection restoration verification (AC02):
   - Disabled airplane mode (adb shell cmd connectivity airplane-mode disable).
   - Tapped retry banner without retyping.
   - Original message ID was reused; status transitioned to 'sent'.
   - Reply was successfully generated and appended to thread.

Result: PASS.
Exact copy matches character-for-character across controller, banner, and persistence.
Input field clears cleanly on send, message is preserved in thread as failed, and retry flow succeeds without duplicate messages.
